# Пульт M33 — управление плеером с телефона по Bluetooth

Два Android-приложения:

| Приложение | Куда ставить | Что делает |
|---|---|---|
| **Пульт M33** (`remote`) | Samsung Fold 7 | Экран управления: обложка, название трека, перемотка, громкость, shuffle/repeat/рейтинг |
| **Приёмник M33** (`receiver`) | FiiO M33 | Висит фоном, принимает команды, управляет играющим плеером и отдаёт состояние обратно |

Связь — прямое Bluetooth-соединение (RFCOMM), без Wi-Fi и без интернета.

На стороне плеера используется системный медиа-контроль Android, поэтому работает
не только Poweramp, но и Neutron, USB Audio Player Pro, любой плеер с медиа-сессией.
Для Poweramp shuffle/repeat/рейтинг дополнительно дублируются через его открытый API —
эти три вещи в медиа-сессии поддержаны не у всех плееров.

## Как собрать APK

Проект — обычный Android Studio / Gradle проект. Два способа.

### Вариант A: GitHub Actions (ничего ставить не надо)

1. Создайте на GitHub пустой приватный репозиторий.
2. Залейте туда содержимое этой папки (кнопка «uploading an existing file» на странице
   пустого репозитория — можно просто перетащить файлы).
3. Вкладка **Actions** → workflow «Сборка APK» → **Run workflow**.
4. Через 5–7 минут внизу страницы запуска появится артефакт `apk` — в нём
   `pult-telefon.apk` и `priemnik-pleer.apk`.

Workflow лежит в архиве по пути `.github/workflows/build.yml`.

Если вы заливаете распакованную папку, а не архив: файл `github-actions-build.yml`
в корне проекта — это тот же workflow. Положите его в репозиторий как
`.github/workflows/build.yml` (Windows не даёт создавать папки с точкой в начале
через проводник — проще создать этот путь прямо на GitHub кнопкой «Create new file»,
вписав в имя `.github/workflows/build.yml`).

### Вариант B: Android Studio

1. Установите Android Studio (любая свежая версия).
2. **File → Open** → выберите эту папку. Studio сама скачает Gradle, Android SDK
   и зависимости, а также допишет недостающий `gradle/wrapper/gradle-wrapper.jar`.
3. Соберите: **Build → Build Bundle(s)/APK(s) → Build APK(s)**,
   либо в терминале Studio:

   ```
   gradlew :remote:assembleRelease :receiver:assembleRelease
   ```

4. Готовые файлы:
   - `remote/build/outputs/apk/release/remote-release.apk` → на телефон
   - `receiver/build/outputs/apk/release/receiver-release.apk` → на плеер

Оба APK подписаны отладочным ключом — ставятся как обычные сторонние приложения,
отдельный keystore не нужен.

## Как настроить после установки

**На плеере FiiO M33** — откройте «Приёмник M33» и пройдите три шага на экране:

1. **Доступ к медиа-сессиям.** Кнопка открывает системный список «Доступ к уведомлениям»,
   в нём нужно включить «Приёмник M33». Без этого приложение не видит, что играет.
   Уведомления не читаются и никуда не передаются — это единственный способ,
   которым Android отдаёт доступ к медиа-сессиям.
2. **Bluetooth.** Нажмите «Сделать видимым на 5 минут» и спарьте плеер с телефоном
   из настроек Bluetooth телефона. Это делается один раз.
3. **Запустить сервис.** Появится постоянное уведомление «Ожидание пульта».

Полезно: в настройках плеера снять ограничение батареи для приложения, иначе
система может убить сервис при спящем экране.

**На телефоне** — откройте «Пульт M33», выберите плеер из списка спаренных устройств.
Дальше приложение подключается само при каждом запуске и переподключается при обрыве.

Качелька громкости телефона, пока пульт открыт и на связи, регулирует громкость плеера.

## Как это устроено

```
телефон                               плеер FiiO M33
┌────────────────┐   RFCOMM/SPP   ┌──────────────────┐   MediaController   ┌──────────┐
│ Пульт M33      │ ─── команды ─→ │ Приёмник M33     │ ─── play/next/… ──→ │ Poweramp │
│ Compose UI     │ ←─ состояние ─ │ foreground-сервис│ ←── метаданные ──── │          │
└────────────────┘   + обложка    └──────────────────┘                     └──────────┘
```

Протокол — кадры `[1 байт тип][4 байта длина][данные]`:
тип 1 — JSON (команды и состояние), тип 2 — JPEG обложки.
Обложка уходит только когда меняется трек.

Состояние летит раз в 2 секунды, позиция трека достраивается на телефоне локально —
поэтому полоса прогресса идёт плавно, а канал почти не грузится.

### Модули

- `shared` — протокол: UUID сервиса, чтение/запись кадров, модель состояния, список команд
- `receiver` — приложение плеера: `ReceiverService` (Bluetooth-сервер) + `MediaHub` (мост к медиа-сессии)
- `remote` — приложение телефона: `LinkService` (соединение и переподключение) + Compose-интерфейс

### Если понадобится править

- Частота отправки состояния и таймауты — `shared/.../Link.kt`
- Логика выбора плеера, когда сессий несколько — `MediaHub.choose()`
- Внешний вид пульта — `remote/.../MainActivity.kt`, цвета в начале файла
